이 지도를 읽는 법

이 페이지는 QuantPilot이 어떻게 돌아가는지(2절 흐름), 사람이 어디서 개입하는지(2절의 "사람" 색 단계), 무엇이 돼 있고 무엇이 빈칸인지(1절 히트맵), 어디를 고쳐야 하는지(3절 갭 목록)를 한 장에 모은 것이다. 프로젝트가 스스로 적어 둔 문서(현황판·수용 매트릭스·런북·체크리스트)를 실제 코드와 맞춰 본 결과이며, 문서와 코드가 다르거나 문서에 없는 것이 "갭"이다.

게이트(Gate)
로드맵의 관문. 하나를 넘어야 다음 단계로 간다. 0·1·2·3·4·P 여섯 개가 있고, "done"은 통과, "proposed"는 아직 계획만 있음.
Level 1~5
자동화 수준. 1~2는 신호를 보고 사람이 모의체결, 3은 제안을 사람이 승인해야 제출, 4는 보호 장치 아래 자동, 5는 완전 자동 오퍼레이터. 3~5는 현재 플래그로 잠겨 있다.
오퍼레이터(Operator)
Level 5의 실행 주체. "한 번의 실행(run-once)"이 게이트 검사→전략 선택→신호→제안→제출→보고의 한 사이클이다.
플래그(flag)
환경변수 스위치. LIVE_TRADING_ENABLED 등 여섯 개가 전부 꺼진 것이 안전 기본값이며, 켜지 않으면 자동 매매 경로는 첫 관문에서 멈춘다.
mock / paper / live
브로커 모드. mock은 가짜 체결, paper는 증권사 모의투자 서버, live는 실거래(코드상 존재하지 않음).
dry_run / mock_submit / paper_submit
실행 모드. dry_run은 제안만 만들고 제출하지 않음. 실거래 모드는 없다.
승인 티켓 / 킬스위치
사람이 개입하는 두 지점. 티켓은 제안을 사람이 승인하는 레일, 킬스위치는 모든 자동 매매를 즉시 멈추고 권한을 낮추는 버튼.
✓ ✗ 와 신뢰도 배지
네모 배지는 "실제로 있다/없다"는 사실. 점선 알약 배지는 "문서 서술이 코드와 같은가"에 대한 판단이며 high/medium/low는 그 판단의 확신 정도. 판단 옆에는 근거 줄이 붙어 있다.

  1. 사람이 안전 체크리스트에 서명하고 정책을 Level 5로 승격한 뒤 "한 번 실행"을 요청한다. 기본 상태에서는 플래그가 꺼져 있어 여기서 이미 멈춘다(STUB-01).
  2. 시스템이 관문 일곱 개를 검사한다 — 플래그, 킬스위치, 브로커 모드, 정책 버전, 승격 여부. 하나라도 실패하면 이유를 적고 끝난다.
  3. 승인된 전략 목록에서 하나를 고른다. 기본 목록에는 승인된 전략이 없어 현재는 항상 "적격 전략 없음"으로 끝난다(MAN-05).
  4. 브로커에서 보유 현황을 받아 온다. 이 직후 특정 전략에서만 타는 숨은 분기가 있다(MIS-03).
  5. 시장 데이터로 신호를 만들고, 포트폴리오 계획과 주문 제안을 만든다. 각 제안에는 리스크 검사 결과가 붙는다.
  6. 제안마다 다시 한 번 전부 검사(시세 신선도, 거래 시간, 주문 유형, 중복 주문…)한 뒤 브로커에 제출한다. dry_run이면 제출하지 않는다.
  7. 보고서를 남긴다. 사람은 API나 화면에서 보고서(상태·중단 이유·결정·주문 id·안전 플래그)를 읽는다.
