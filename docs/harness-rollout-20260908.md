# 전역 하네스 재구성 적용 결과 — 2026-09-08

aorch 공통 원본과 프로젝트별 원본을 분리하고 전역 및 등록된 10개 설치 경로에 반영했다. 원래 저장소에 변경을 통합했으며 commit·push·PR·배포·브로커 쓰기는 수행하지 않았다.

## 적용 내용

- 공통 에이전트 15개·스킬 4개는 integrations/shared, 개인 공통 에이전트 5개·스킬 25개는 integrations/user에서 관리한다. 27개 기존 사용자 스킬 폴더는 삭제하지 않고 백업으로 보관했다. 제품별 파일 수는 호환성 제공을 위해 늘 수 있으며, 중복 원본과 항상 읽는 절차를 줄이는 것이 목적이다.
- 주식트레이더 본 작업공간은 프로젝트 에이전트 16개·스킬 11개를 이관했다. 8개 에이전트와 vault-consult는 Claude 요구 조건을 보존해 Codex에 안내용 연결을 생성했다. 이전 모델 업그레이드 worktree의 8개 에이전트·10개 스킬도 그 작업공간의 본문을 유지해 이관했다.
- 책의 8개 스킬은 저장소 .agents/aorch/skills가 원본이다. 전역의 책 스킬 7개는 이 원본으로 연결한다. 제품별 생성 시 프로젝트 외부 참조 링크의 상대 경로를 보정한다.
- 고정 역할 수, 항상 만드는 계획·작업보드, 중복 계획 제어와 프롬프트마다 실행되던 업데이트·모델 거절 훅을 정리했다. 로컬 설정에서 실제 Superpowers marketplace ID를 비활성화했고, 별도 인터뷰 강제 훅을 설정에서 분리했다. 외부 플러그인 캐시는 수정하지 않았다.
- inventory는 에이전트·스킬·플러그인·훅, 플러그인 내부 정의, 출처, 설치·설정·관측된 사용 가능 여부와 동기화를 구분한다. 여러 캐시 중 실제 경로가 불명확하면 실행 가능하다고 간주하지 않는다. 전체 카탈로그를 상시 읽지 않고 --type/--match로 좁혀 조회한다.
- agentId, blocked.inputRequest, 답변 전달, 실패 지점부터 명시적 재개, 동일 재개 명령의 중복 실행 방지를 기존 CLI에 통합했다. native 모델 설정은 대화형 기본값이며 aorch 비대화형 실행 모델은 기존 라우터가 정한다. 특정 모델 요구는 allowedProfileIds로 고정한다.

## 확인 범위와 남은 제약

완료 직전 현재 Codex 앱 대화에 새 전역 AGENTS와 공통·개인 스킬 목록이 갱신되어 노출된 것을 확인했다. [부분 앱 관측 기록](../.aorch/harness-evidence-20260908/app-observation.json)에 실제 노출된 43개 스킬 ID를 기록했다. 다만 Superpowers 14개 스킬은 로컬 설정의 enabled=false와 달리 현재 대화 목록에 계속 노출된다. 설정 비활성화를 앱에서 완전히 제거된 상태라고 보고하지 않는다. aorch 우선 워크플로는 갱신된 사용자 지침에 적용됐으며, 앱의 native 에이전트 직접 호출은 별도로 검증하지 않았다. 파일 생성·TOML 파싱·Codex CLI·Claude Code·aorch 비대화형 실행 증거와 이 앱 관측을 구분한다.

Fable 호출은 사용량 한도에 막혔고 Opus로 독립 검토와 실제 위임을 확인했다. 기존 node_repl MCP는 앱에 노출되지만 CLI에서 handshake 오류가 관찰되어 이 차이를 기록했다. 앱 기능까지 제거하는 전역 비활성화는 하지 않았다. 실제 거래·외부 서비스 쓰기나 책 출판·전체 PDF acceptance는 이 하네스 변경의 대표 검증 범위에 포함하지 않았다.
