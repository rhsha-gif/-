# 매매 알고리즘 지도 (algo-map) v1 — pullback_trend_v2 on real KRX bars

## 목표

QuantPilot의 실제 결정 함수 `evaluate_pullback_signal`(v2 규칙)을 실 KRX 일봉에 물려 봉별 판정·지표·reason_codes와 백테스트 결과를 JSON으로 뽑고, 규칙 표·흐름도·캔들 차트(진입/청산·발화 규칙)·성과·개선 신호를 담은 아티팩트 한 장을 만들어, 1회차에 "값을 바꿔 재실행해 보고 싶은 규칙·임계값이 하나라도 나왔는가(몇 개·어느 필드)"를 기록하면 끝이다.

## 접근

2026-09-04 인터뷰 3라운드 + 포니테일 점검(주장 3건을 코드로 검증). 재실행이 전제이므로 Fable이 HTML을 쓰지 않고 **QuantPilot의 트레이스 잡 + aorch의 렌더 스크립트** 두 단계로 고정한다. 기존 백테스트 엔진·지표·검증을 재사용하고 새 계산은 최소화한다.

포니테일이 밝힌 사실(검증됨):
- **A.** `run_local_backtest`→`replay_signals`는 Level 1-2용 `classify_fixture_bar`(리터럴 임계값 ma20×0.94·RSI 72/35·거래량 1.1)를 부른다. `evaluate_pullback_signal`은 라이브 경로(`signals/service.py:689`)에서만 불린다. 지금까지의 백테스트 수치는 v2 규칙의 것이 아니다.
- **B.** v1 레시피에는 `decision_rules`가 없고 v2는 `schemas.py:243` 검증기가 기본값과 다르면 거부한다. v1·v2 임계값 차이는 0이다(비교 삭제).
- **C.** 18개 필드 중 `hard_stop_loss_fraction`(risk/position_exit.py에서 사용)·`atr_stop_multiplier`·`max_candidates`·`rebalance_band` 4개는 `evaluate_pullback_signal`이 읽지 않는다(표에서 분리 표기).

| 6 | 개선 신호: 차단 코드 빈도(스텁 게이트는 별도 표기), 신호 후 미체결(`status=blocked`) 비율, 수용 임계값·워크포워드 창별 불합격. "청산 후 N봉 회복"은 판정 문구 없이 원자료 목록만, 청산 거래 10건 미만이면 비율 미계산 |
| 7 | 제외: v1·v2 비교, 파라미터 스윕, Fable HTML 작성, `run_local_backtest` 분류기 교체(이월) |
| 8 | 측정: 재실행하고 싶은 규칙·임계값 수와 필드명 |
