# Adaptive Orchestrator v0.7.0 Subscription-First Minimal Sound Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mechanically enforced bootstrap-only orchestrator for the user's real environment: Codex desktop app, ChatGPT-authenticated Codex CLI, and subscription-authenticated Claude Code CLI, with no automatic API/PAYG/cloud fallback.

**Architecture:** Add a subscription-local client plane before the existing v0.7 safety work. Separate host surfaces from worker transports, validate subscription authentication and credential precedence, bind native Claude subagent use to one-time permits, and treat provider usage as quota pressure rather than API cost. Then enforce the host boundary, captured-content attestation, hidden verification, conservative reliability evidence, and lifecycle operations defined by the minimal-sound-core design.

**Tech Stack:** Node.js 20+ ESM, native `node:test`, Git linked worktrees, Codex app/CLI, Claude Code CLI, JSON/JSONL file-first state.

## Global Constraints

- Default deployment profile is `subscription-local`.
- Do not add direct OpenAI/Anthropic SDK or HTTP API calls.
- Do not automatically use API keys, PAYG, usage credits, custom gateways, cloud providers, or Codex cloud tasks.
- Codex app is a host surface; Codex CLI is the automation-capable OpenAI worker transport.
- Claude Code host may use only a permit-bound managed native subagent; cross-host Anthropic work uses subscription-authenticated `claude -p`.
- Interactive Claude and `claude -p` share one Anthropic subscription pool until official policy actually changes.
- The host is bootstrap-only for every substantive task and cannot edit product files.
- Low-risk coherent work remains one delegated worker call, not host-direct execution.
- Receipt is a claim; only a passing attestation bound to a captured snapshot may complete a task.
- Prompt templates are informed by official guidance but are not represented as automatically derived from remote documents.
- Official-guidance age produces warnings and fallback, never a date-triggered fleet outage.
- Persistent record-only shadow state is removed.
- Do not add runtime dependencies, a daemon, database, queue, dashboard, nested scheduler, or online reinforcement learning.
- All behavior changes use red-green TDD and focused commits.
