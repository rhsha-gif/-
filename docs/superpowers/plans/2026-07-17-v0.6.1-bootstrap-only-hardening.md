# Adaptive Orchestrator v0.6.1 Bootstrap-Only Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Correct v0.6.0 so the host always bootstraps a separate bounded worker, low-risk work uses one coherent worker call, and unsafe routing or stale prompt-profile inputs fail closed.

**Architecture:** Replace the host-direct lane with `single-worker`, centralize monotonic lane resolution, separate external-action detection from file-mutation intent in the thin gate, remove implicit provider trust, and validate prompt-profile provider provenance and freshness before compilation. Preserve dependency-free Node.js ESM, file-first state, independent verification, record-only shadow metadata, and proposal-only control-plane changes.

**Tech Stack:** Node.js 20+ ESM, native `node:test`, JSON/JSONL state, Git worktrees, Claude Code CLI, Codex CLI.

## Global Constraints

- The host execution mode is always `bootstrap-only`; host route preference may still be `preferred`, `pinned`, or neutral.
- No substantive project task may use host-direct execution.
- `single-worker` low-risk work uses one task, one delegated worker call, zero separate router-model calls, zero LLM reviewers, and no executing shadow.
- Explicit lane input may only strengthen the classifier's base lane.
- No external runtime dependencies, daemon, database, nested scheduler, or automatic harness self-editing.
- Prompt profiles must cite provider-owned official domains and satisfy freshness policy.
- Worker output remains a claim; verifier attestation remains the only completion evidence.
