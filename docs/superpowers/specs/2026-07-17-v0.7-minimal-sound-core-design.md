# Adaptive Orchestrator v0.7.0 Subscription-First Minimal Sound Core Design

## 1. 목적

v0.7.0은 v0.6.x에 기능을 계속 덧붙이는 릴리스가 아니다. 1차 원리 검토에서 확인된 구조적 모순을 제거하고, 사용자의 실제 실행 환경에 맞는 최소 건전 코어를 만드는 릴리스다.

핵심 문장은 다음과 같다.

> Host는 bootstrap-only이며, 구독으로 인증된 공식 로컬 클라이언트를 통해 bounded worker를 실행한다. Worker의 완료 주장은 특정 변경 snapshot에 결속된 독립 검증을 통과하기 전에는 완료 증거가 아니다.

사용자 목표는 그대로 유지한다.

```text
사용자가 Codex 앱 또는 Claude Code CLI에 프롬프트 입력
→ host가 요청을 과도하지 않은 단위로 분해
→ 작업별 provider/model/effort/capability 선택
→ 공식 provider 가이드를 반영한 provider-aware prompt 생성
→ 구독 인증 local worker 실행
→ 독립 verifier
→ 결과 통합과 회고
```

저위험·단순 작업도 host가 직접 구현하지 않는다. 하나의 coherent task와 worker 1회 호출로 묶어 별도 모델 호출을 최소화한다.

## 2. 기준 사용자 환경

v0.7.0의 기본 배포 프로필은 `subscription-local`이다.

```text
OpenAI host: ChatGPT desktop app의 Codex view
OpenAI worker: 같은 ChatGPT 계정으로 로그인한 Codex CLI
Anthropic host: Claude Max/Pro 구독으로 로그인한 Claude Code CLI
Anthropic same-host worker: permit-bound Claude native subagent
Anthropic cross-host worker: subscription OAuth를 사용하는 claude -p
직접 OpenAI/Anthropic HTTP API: 기본 사용 안 함
API key·custom endpoint·cloud provider transport: 기본 사용 안 함
Codex cloud delegation: 기본 비활성
추가 usage credit 또는 PAYG fallback: 기본 비활성
실행 위치: local repository와 managed Git worktree
```

### 2.1 Host surface와 worker transport

```text
Codex app            = OpenAI host UI
Codex CLI            = OpenAI automation 가능한 local worker transport
Claude Code CLI      = Anthropic host UI
Claude native Agent  = Claude-host 내부의 same-provider worker transport
claude -p            = Codex-host 등에서 사용하는 cross-host Anthropic worker transport
```

Codex 앱은 local folder·repository·terminal·developer tool을 다루는 host surface다. 앱 자체를 문서화되지 않은 IPC나 subprocess API로 제어하지 않는다. OpenAI worker가 필요하면 공식 Codex CLI를 호출한다.

Codex 앱의 프로젝트 hook/PreToolUse 지원은 설치된 앱 버전과 공식 지원 표면을 실제로 확인해야 한다. v0.7.0은 앱에서 strict host enforcement가 검증되지 않았는데도 기계적 강제를 제공한다고 주장하지 않는다. `aorch doctor --surface codex-app`는 `strict|advisory|unsupported|unknown`을 보고하고, authenticated app smoke가 없으면 release report는 Codex 앱 경계를 `not verified`로 표시한다. Strict bootstrap-only가 필수인데 앱 hook이 지원되지 않으면 Codex CLI host 또는 별도의 read-only host workspace를 사용해야 한다.

Claude Code host에서는 동일 subscription session 안의 native subagent를 우선한다. 단, host가 임의의 Agent를 생성하지 못하도록 `aorch`가 발급한 일회성 dispatch permit과 정확히 일치하는 managed `aorch-worker`만 허용한다.

2026-07-17 현재 Anthropic의 최신 지원 문서는 별도 Agent SDK credit 전환이 일시 중지되어 있으며, `claude -p`와 Agent SDK 사용도 계속 구독 사용량 한도에서 차감된다고 명시한다. 따라서 v0.7.0은 interactive Claude Code와 `claude -p`를 **하나의 `anthropic-subscription` pool**로 취급하되, 진단을 위해 transport별 사용 흔적은 따로 기록한다. 향후 공식 정책이 실제로 변경되면 capability manifest 갱신과 검증된 migration을 거쳐 pool을 분리한다.

### 2.2 API를 거의 사용하지 않는다는 의미

기본값은 API를 완전히 삭제하는 것이 아니라, 자동 경로에서 제외하는 것이다.

```text
subscription-local
→ API key 불필요
→ API credential 상속 금지
→ API/PAYG 자동 fallback 금지
→ cloud task 자동 위임 금지

explicit-api
→ 사용자가 해당 run에서 명시적으로 선택
→ credential·비용·데이터 경계 재검증
→ subscription run과 별도 trace
```

v0.7.0의 필수 구현 범위는 `subscription-local`이다. `explicit-api`는 향후 확장 가능한 정책 이름과 fail-closed 경계만 정의하며, 직접 SDK/HTTP transport 구현은 필수 범위에 포함하지 않는다.

## 3. 범위

### 포함

1. Claude·Codex host의 제품파일 직접 편집을 `PreToolUse` 계층으로 제한한다.
2. 성공 task/run 상태를 passing attestation에 결속한다.
3. Attestation을 captured workspace snapshot에 결속하고 live workspace TOCTOU를 제거한다.
4. Hidden check 보호와 최소 실행검사 정책을 추가한다.
5. Prompt profile의 날짜 기반 fleet outage를 제거하고 provider-aware template로 정직하게 낮춘다.
6. Gate regex를 최종 분류기가 아닌 risk floor로 축소한다.
7. 실행하지 않는 persistent shadow를 제거하고 ephemeral alternative explanation으로 대체한다.
8. Attestation 기반 execution-reliability observation을 자동 기록하되 제품 품질과 동일시하지 않는다.
9. 설치 산출물 손복제를 줄이고 dead native agent profile을 제거하거나 permit-bound worker 하나로 통합한다.
10. State retention·compaction, worktree provisioning, upgrade/uninstall 경로를 추가한다.
11. Codex 앱·Codex CLI·Claude Code CLI를 구독 인증 local client surface로 모델링한다.
12. Subscription-only 인증 검증, API credential 충돌 탐지, 사용량 pressure 정책을 추가한다.
13. Claude Code host에서는 permit-bound native subagent를 우선하고, cross-host `claude -p`는 동일 Anthropic subscription pool의 별도 transport로 추적한다.
14. 모델 availability는 API catalog 가정이 아니라 설치된 client의 정적 검사와 opt-in live probe로 확인한다.
15. 실제 provider usage가 제공되면 기록하되 API 가격을 구독 비용으로 환산하지 않는다.

### 제외

- 외부 DB·daemon·queue·dashboard
- production 중 자동 harness source 수정
- 온라인 강화학습
- 실제 write shadow 실행
- 원격 공식문서 snapshot 재배포
- 모든 언어·빌드 시스템의 완전한 hermetic verification
- 모든 shell path를 완전히 가로막는다는 주장
- OpenAI·Anthropic API SDK 또는 직접 HTTP 호출
- API key fallback과 자동 credit 구매
- Codex cloud task의 기본 사용
- Codex desktop app을 비공식 subprocess API로 제어하는 구현
- 제공자가 노출하지 않는 구독 잔여량의 정밀 퍼센트 추정
- model slug가 존재한다는 이유만으로 entitlement가 있다고 가정하는 동작

## 4. 핵심 불변식

1. `AORCH_WORKER=1`이 아닌 host는 제품 파일을 직접 편집할 수 없다.
2. Host가 쓸 수 있는 경로는 `.aorch/inbox/**`의 task envelope뿐이다.
3. Host Bash는 `aorch` 명령과 제한된 read-only command만 허용된다.
4. `complete`, `accepted`, `done` task 상태는 `status: pass` attestation 없이는 기록할 수 없다.
5. `completed` run은 모든 비-skip task에 유효한 attestation이 있어야 한다.
6. Attestation은 base HEAD, captured patch hash, per-file fingerprint, snapshot digest에 결속된다.
7. Isolated verifier는 live workspace가 아니라 captured patch와 snapshot files에서 materialize한다.
8. Standard 이상의 write task는 실행검사 최소 1개가 필요하다.
9. Hidden verifier check가 보호하는 file/pattern을 worker가 바꾸면 검사 실행 전 실패한다.
10. Prompt guidance가 오래됐다는 이유만으로 전체 실행이 중단되지 않는다. 경고와 provider generic fallback을 사용한다.
11. Gate regex는 위험도를 올릴 수만 있고 내릴 수 없다. 최종 task risk는 host structured classification과 floor의 최댓값이다.
12. Counterfactual alternative는 실제 성능 evidence가 아니다.
13. 자동 observation은 execution reliability만 기록하며 제품 품질 점수라고 부르지 않는다.
14. Control-plane 승인에는 interactive human confirmation 또는 명시적 CI approval token이 필요하다.
15. 설치본과 package source는 동일한 hook runtime source에서 생성된다.
16. 기본 access mode는 `subscription-local`이며 direct API transport는 route 후보가 아니다.
17. Subscription worker에 API key, bearer token, custom base URL, Bedrock·Vertex·Foundry override를 상속하지 않는다.
18. Codex worker는 ChatGPT sign-in을 사용하는 local `codex` CLI로 실행한다. Codex 앱은 host surface다.
19. Claude native subagent는 일회성 permit에 결속된다. 다른 host Agent invocation은 거부된다.
20. `claude -p`는 subscription OAuth만 허용하고 API credential이 우선하는 환경에서는 실행을 거부한다.
21. Interactive Claude와 `claude -p`는 2026-07-17 현재 하나의 `anthropic-subscription` usage pool을 공유한다.
22. API 가격을 subscription 비용으로 환산하지 않는다. Usage pressure는 품질 동등 후보의 tie-break와 exhausted eligibility에만 사용한다.
23. 모델 live probe는 명시적 사용자 동의가 있어야 하며 probe 자체가 구독 사용량을 소비할 수 있음을 표시한다.
24. 한도 도달 시 기본 정책은 다른 사용 가능한 subscription provider로 재라우팅하거나 block/wait이다. API·credit·cloud로 자동 전환하지 않는다.
25. Provider가 잔여량을 정확히 노출하지 않으면 오케스트레이터는 숫자를 만들어내지 않는다.
26. Codex 앱에서 strict host enforcement를 주장하려면 공식 hook/policy 지원과 authenticated smoke evidence가 필요하다. 확인되지 않은 경우 enforcement level을 `advisory` 또는 `unknown`으로 표시한다.

## 5. Subscription client plane

### 5.1 Target configuration

구현 목표 설정은 `config/subscription-local.target.json`에 별도 제공한다. v0.6.1 기준선의 실행 config와 혼동하지 않는다.

```json
{
  "access": {
    "profile": "subscription-local",
    "localOnly": true,
    "allowDirectApi": false,
    "allowApiFallback": false,
    "allowCloudDelegation": false,
    "allowPaidCredits": false,
    "overflowPolicy": "reroute-or-wait"
  },
  "surfaces": {
    "openai": {
      "host": "codex-app",
      "workerTransport": "codex-cli",
      "auth": "chatgpt-oauth",
      "usagePool": "openai-agentic"
    },
    "anthropic": {
      "host": "claude-code-cli",
      "sameHostWorkerTransport": "claude-native-subagent",
      "crossHostWorkerTransport": "claude-print",
      "auth": "subscription-oauth",
      "usagePool": "anthropic-subscription"
    }
  }
}
```

### 5.2 인증과 credential precedence

`aorch doctor --subscription`은 다음을 검사한다. `aorch doctor --surface codex-app`는 별도로 Codex 앱의 host enforcement 수준을 검사한다.

#### Claude

- `claude auth status`가 로그인 상태를 machine-readable하게 보고하는가
- subscription OAuth가 active credential인가
- `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`이 존재하는가
- `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`가 존재하는가
- `CLAUDE_CODE_OAUTH_TOKEN` 또는 `apiKeyHelper`가 interactive subscription과 다른 자동화 credential을 유발하는가
- `/status` 또는 auth status에서 login expiry를 사전에 확인할 수 있는가

Claude Code 공식 인증 우선순위상 cloud-provider override, auth token, API key가 subscription OAuth보다 먼저 선택될 수 있다. Subscription-local mode에서는 이 충돌을 warning으로만 남기지 않고 worker 실행 전에 차단한다.

#### Codex

- Codex 앱의 공식 프로젝트 instruction/hook 표면과 현재 버전을 확인한다.
- Strict `PreToolUse` 차단이 실제 앱에서 지원·실행되는지 authenticated fixture로 확인한다.
- 확인되지 않으면 `enforcement: unknown|advisory`로 보고하고 strict라고 표시하지 않는다.
- Codex CLI executable과 version을 확인한다.
- 현재 공식 client가 제공하는 auth-status command가 있으면 ChatGPT sign-in 상태를 확인한다.
- Machine-readable auth status가 없다면 `unknown`으로 표시하고, 저위험 read-only canary 전에는 critical executor로 활성화하지 않는다.
- `OPENAI_API_KEY`, custom base URL, third-party provider 설정이 발견되면 subscription-local 실행을 차단하거나 명시적 사용자 해소를 요구한다.
- Codex 앱의 로그인 상태나 hook 지원을 파일·비공식 IPC로 추측하지 않는다.

#### Worker environment

Parent environment를 통째로 전달하지 않는다.

```text
allow:
  PATH, HOME/USERPROFILE, TMPDIR/TEMP, locale, terminal-required variables,
  provider가 문서화한 subscription OAuth credential store 접근에 필요한 최소값

deny:
  API keys, bearer tokens, custom endpoints, cloud-provider selection,
  usage-credit auto-enable flags, unrelated secrets
```

### 5.3 모델 availability와 entitlement

Package catalog의 model profile은 “원하는 route 후보”이지 “계정에서 사용 가능함”을 뜻하지 않는다.

```text
aorch models inspect
→ client/version/config/profile 정적 검사
→ model call 없음

aorch models probe --live --provider <id> --profile <id>
→ 명시적 확인 후 작은 read-only task 실행
→ subscription 사용량 소비 가능
```

상태:

```text
unknown | available | unavailable | temporarily-limited
```

정책:

- Probe하지 않은 profile은 `unknown`이다.
- Critical executor는 `unknown` profile을 사용할 수 없다.
- User가 현재 host UI에서 직접 선택한 model/effort는 그 session에서 `host-observed`로 기록할 수 있지만, worker entitlement 증거로 자동 승격하지 않는다.
- Provider alias가 실제 backend revision을 노출하지 않으면 revision을 임의로 추정하지 않는다.

### 5.4 구독 사용량 pool

```text
openai-agentic
  Codex와 해당 plan의 다른 agentic 기능이 공유할 수 있는 pool

anthropic-subscription
  Claude, Claude Code interactive/native subagent, claude -p/Agent SDK가
  현재 정책상 공유하는 subscription usage pool
```

모든 pool은 다음 상태만 가진다.

```text
unknown | green | yellow | red | exhausted
```

상태 출처:

- provider가 표시한 usage/limit output
- 사용자의 명시적 입력
- 실제 rate/usage-limit 오류
- 60분 이내의 provider last-known snapshot임이 명시된 값

금지:

- API token 가격으로 subscription 잔여량 환산
- 정적인 `tokenIndex`를 실제 구독 소비량이라고 표시
- 서로 다른 provider의 quota를 하나의 달러 비용으로 합산

라우팅 순서:

```text
risk/trust/entitlement eligibility
→ expected quality와 evidence confidence
→ 품질 허용오차 이내 후보
→ usage pressure
→ latency
```

Usage가 red라는 이유만으로 품질 하한을 깨는 모델을 선택하지 않는다.

### 5.5 한도 도달 정책

```text
primary provider exhausted
→ 같은 provider의 사용 가능한 모델/transport 검토
→ 품질 하한을 만족하는 다른 subscription provider 검토
→ 없으면 block/wait와 reset 정보 표시
```

기본 동작으로 하지 않는 것:

- API key 사용
- PAYG 또는 usage credit 활성화
- credit 구매 화면 자동 조작
- Codex cloud task로 자동 위임
- 사용자가 선택하지 않은 external gateway 사용

## 6. 제어 흐름

### 6.1 Prompt 진입

`UserPromptSubmit` hook은 다음만 수행한다.

- 높은 recall의 위험 floor 계산
- session/thread용 orchestration marker 기록
- bootstrap-only host 계약 주입
- 현재 deployment profile이 `subscription-local`임을 host context에 주입

분해·inventory·route scoring·lesson retrieval·provider probe는 hook 밖에서 수행한다.

### 6.2 Host 강제

Claude Code와 공식적으로 지원되는 Codex host surface에 `PreToolUse` policy를 설치한다. Codex 앱에서 동일 hook이 검증되지 않으면 strict enforcement를 주장하지 않고 doctor가 경고한다.

허용:

- read-only native tool
- `.aorch/inbox/**` task envelope 작성
- 승인된 `aorch` command
- 제한된 read-only shell command
- permit-bound Claude `aorch-worker` Agent invocation

거부:

- Host의 프로젝트 `Edit`/`Write`/`apply_patch`
- 보호된 control-plane 파일 변경
- shell redirection, command substitution, chained mutating command
- `AORCH_WORKER` 위조
- permit 없는 Agent/subagent invocation
- API credential 주입 또는 fallback enable 명령
- cloud delegation/credit purchase 관련 자동 조작

Hook은 OS sandbox가 아니다. Worker transport의 sandbox, permission profile, worktree를 함께 사용한다.

### 6.3 Task 실행

#### 저위험·단순 작업

```text
single-worker lane
→ task 1개
→ worker 호출 1회
→ verifier
```

Claude host에서 Anthropic worker가 선택되면 permit-bound native subagent가 우선이다. Codex app host에서 OpenAI worker가 선택되면 local Codex worker transport를 사용한다. Cross-provider가 필요할 때만 다른 provider CLI를 호출한다.

#### 복잡·고위험 작업

```text
orchestrated lane
→ 독립 승인 가치가 있는 task만 분리
→ task별 worker
→ verifier + 필요한 review
```

저위험 task를 파일 탐색·수정·테스트로 별도 모델 호출에 분해하지 않는다.

## 7. 검증 snapshot

### 7.1 캡처

Worker 종료 직후 다음을 한 번 캡처한다.

- base HEAD
- `git diff --binary HEAD` bytes와 SHA-256
- tracked/untracked/evidence file fingerprint
- untracked/evidence file immutable snapshot copy
- snapshot manifest digest

Verifier는 이후 live workspace에서 patch를 다시 읽지 않는다.

### 7.2 Materialization

`git-worktree` verifier는 base HEAD에서 detached worktree를 만든 후:

1. captured patch 적용
2. captured untracked/evidence snapshot 복사
3. copied content fingerprint 재검사
4. sanitized environment에서 prepare/check 실행

### 7.3 Attestation

Attestation v2:

```json
{
  "schemaVersion": 2,
  "baseHead": "...",
  "snapshotDigest": "...",
  "patchSha256": "...",
  "files": [{"path":"...","fingerprint":"..."}],
  "checks": [],
  "status": "pass|fail|inconclusive"
}
```

State update는 attestation을 다시 읽고 digest·taskId·runId·status를 검사한다.

## 8. Hidden check와 test gaming

Task는 다음을 지원한다.

```json
{
  "verifierProtectedScope": ["package.json", "scripts/verify/**", "hidden-tests/**"],
  "allowChangeEvidenceOnly": false,
  "verifierPrepareCommands": ["npm ci --ignore-scripts"],
  "verifierCommands": ["npm test"]
}
```

Private task envelope와 public worker envelope를 분리한다. Worker에게 공개하지 않는 값:

- verifier commands
- protected scope
- approval secret
- CI token
- parent conversation history
- auth/usage pool credential detail

Standard/high/critical write task는 실행검사 최소 1개가 필요하다. Worker 변경이 protected scope와 겹치면 check 실행 전 fail한다.

## 9. Prompt template plane

Prompt는 provider-neutral task envelope에서 시작한다.

```text
canonical task
→ provider/model strategy
→ provider-aware local template
→ lint
→ worker transport
```

정확한 명칭:

> 공식 provider 가이드를 참고해 작성한 versioned provider-aware prompt template

다음 표현은 사용하지 않는다.

> 공식 문서에서 자동 컴파일된 prompt

Template stale 정책:

- source ownership 불일치: fail
- stale verified date: warning
- known family profile 없음: provider balanced fallback
- unknown future model: generic balanced fallback + warning

Subscription profile에서는 prompt가 API endpoint·SDK usage를 전제하지 않게 한다. Codex 앱/CLI와 Claude Code의 실제 tool·permission·structured-output 표면을 기준으로 작성한다.

## 10. Routing evidence

### 10.1 Policy prior

Catalog의 quality는 학습된 진실이 아니라 보수적인 정책 prior다.

### 10.2 Reliability evidence

Attestation에서 자동 생성:

- pass: uncertainty 감소만 허용
- fail: route reliability 감점
- inconclusive: 품질 증거로 사용하지 않음

Pass만 반복돼도 configured prior보다 위로 자동 승격하지 않는다.

### 10.3 Alternative candidate

Route response에 optional `alternative`를 포함할 수 있다.

```json
{
  "selected": {"profileId":"..."},
  "alternative": {
    "profileId":"...",
    "executed": false,
    "evidenceClass":"counterfactual-only"
  }
}
```

장기 outcome journal이나 promotion evidence로 사용하지 않는다.

### 10.4 Host와 worker 사용 흔적

Trace는 역할을 분리한다.

```text
host surface
host selected model/effort
worker transport
worker model/effort
prompt profile
subscription pool
provider-reported usage if present
limit or reroute event
verifier status
```

Provider가 usage를 보고하지 않으면 값을 추정해 채우지 않는다.

## 11. Durable state와 운영

### 11.1 Journal

기존 lock/checksum/hash-chain을 유지한다. 설치 hook runtime은 package source 한 곳에서 vendoring한다.

### 11.2 Retention

```bash
aorch compact
aorch compact --apply
```

Preview가 기본이다. Archive에는 source journal digest와 범위를 기록한다.

### 11.3 Worktree

```bash
aorch worktree create --name <id>
aorch worktree list
aorch worktree remove --name <id>
```

Managed directory가 Git ignore/local exclude에 없으면 생성하지 않는다.

### 11.4 Upgrade와 uninstall

```bash
aorch install --upgrade
aorch uninstall
```

Managed file hash manifest를 사용한다. 사용자 수정 파일은 자동 덮어쓰기·삭제하지 않는다.

### 11.5 Subscription operations

```bash
aorch doctor --subscription
aorch models inspect
aorch models probe --live
aorch usage show
aorch usage set --pool <id> --state <state> --source user
```

`usage set`은 provider quota를 발명하는 명령이 아니라 사용자가 실제 UI에서 확인한 상태를 기록하는 명령이다. 기록에는 source와 timestamp가 필요하다.

## 12. 승인

Interactive 승인:

- TTY 필요
- proposal digest 표시
- exact confirmation text 입력
- approval hash-chain journal 기록

CI 승인:

- explicit one-time token
- configured digest와 일치
- 사용 후 소비

Host가 일반 Bash를 통해 자신의 proposal을 승인할 수 없다. Subscription credit 활성화, API fallback, cloud delegation도 control-plane 승인만으로 자동 허용되지 않으며 별도의 user-facing access-profile 변경이 필요하다.

## 14. 호환성과 마이그레이션

v0.6.x에서 제거하거나 변경:

- host-direct 경로 제거 유지
- persistent shadow trace 제거
- prompt-profile age fail-closed 제거
- native agent 다수를 제거하고 permit-bound `aorch-worker` 하나로 대체
- direct API transport를 기본 route에서 제거
- `tokenIndex`를 실제 subscription 비용으로 표시하지 않음
- Anthropic interactive와 `claude -p`를 별도 pool로 가정하지 않음

기존 v0.6.1 실행 config는 baseline 테스트용으로 남는다. 구현 과정에서 migration이 완료되기 전까지 target config와 혼합하지 않는다.

## 15. 구현 완료 기준

v0.7.0 구현은 다음이 모두 충족돼야 한다.

1. Subscription-local profile이 기본이고 API credential conflict가 fail closed한다.
2. Codex 앱 host와 Codex CLI worker가 문서·trace·config에서 분리된다.
3. Claude native subagent permit과 cross-host `claude -p` 경계가 테스트된다.
4. API·paid credit·cloud fallback이 자동으로 발생하지 않는다.
5. Host bootstrap-only 강제가 실제 hook policy에 존재한다.
6. Task/run completion이 captured-content attestation에 결속된다.
7. Hidden verification plan이 worker에게 노출되지 않는다.
8. Gate가 monotonic risk floor로 동작한다.
9. Prompt stale state가 fleet outage를 만들지 않는다.
10. 자동 evidence는 reliability만 조정하며 품질 prior를 올리지 않는다.
11. 전체 테스트, clean package install, clean ZIP replay를 통과한다.
12. 실제 provider 호출을 실행하지 않았다면 그 한계를 release report에 명시한다.
