# 마감 (ship)

"커밋해" 한 마디로 검증→커밋까지 무확인 진행. 사람 게이트는 푸시 직전 딸깍 1회뿐이다.

## 절차

### 1. 검증 명령 탐색
프로젝트의 `CLAUDE.md` → `AGENTS.md` → `package.json`/`pyproject.toml`/`Makefile` 순으로 검증 명령을 찾는다.
프로젝트 이름 하드코딩 없음 — 항상 현재 저장소의 규약이 기준이다.
변경 범위에 해당하는 명령만 실행한다 (예: 백엔드만 바뀌었으면 프론트 빌드 생략).

### 2. 검증 실행 (Iron Law)
- 통과 출력을 직접 확인하기 전에는 커밋하지 않는다.
- **실패 시: 커밋하지 않고 원인 수정이 우선.** 테스트 약화·스킵·경고 무시로 통과시키는 것 금지.
- 검증 명령을 찾지 못했으면 그 사실을 보고하고 커밋 여부를 AskUserQuestion으로 확인한다.

### 3. 시크릿 검사
`git diff --cached`(스테이징 후)에서 `.env`, 토큰, API 키, 개인키, 자격 증명 패턴이 포함되지 않았는지 확인한다. 발견 시 즉시 언스테이징하고 보고한다. 보고에는 파일 경로와 패턴 종류만 적고 값은 인용하지 않는다.

### 3.5 프로젝트 보안 게이트 (있을 때만)
저장소의 `.claude/agents/*.md` 중 frontmatter에 `ship_triggers:` 글롭 목록을 가진 에이전트가 있고, 스테이징된 파일 중 하나라도 그 글롭에 걸리면 커밋 전에 게이트를 통과해야 한다.
1. 프로젝트에 `scripts/security-gate.ps1`이 있으면 `powershell -ExecutionPolicy Bypass -File scripts/security-gate.ps1 -Staged`를 먼저 돌린다(도구 증거 수집; exit 1이면 도구 실행 실패 = 게이트 미통과).
2. Agent 도구로 그 에이전트를 호출해 증거 디렉터리 경로를 주고 `verdict`를 받는다.
3. `verdict: block`이면 **커밋하지 않는다.** findings를 표(id·severity·path·rule·proposal)로 보고하고 AskUserQuestion으로 "수정 후 재검사 / 사용자 책임으로 커밋 / 중단"을 묻는다. `pass`면 4단계로.
트리거에 걸리지 않으면 이 단계는 건너뛰고 보고에 "보안 게이트: 트리거 없음"이라고 적는다.

### 4. 커밋 (무확인)
- 서로 무관한 변경은 논리 단위로 나눠 여러 커밋으로 만든다.
- 커밋 메시지: 영어 명령형 한 줄 요약 + 필요시 본문. 저장소에 커밋 스코프 관례가 있으면 따른다.
- 여기까지는 추가 승인 없이 진행한다 (permissions에서 허용됨).

### 5. 푸시 게이트 (딸깍 1회)
- 원격이 있으면 AskUserQuestion 1회: "푸시할까요? [푸시 / 커밋까지만]".
- 원격이 없으면 커밋까지만 하고 그 사실을 보고한다.
- 사용자가 처음부터 "푸시해"/"푸시까지"라고 명시했으면 이 게이트를 생략하고 바로 푸시한다.
