# Project Health Check

과거 세션에서 "프로젝트 파악 → 디버깅 계획 → 실사용 문제 해결 → 리팩토링" 요청이 3회 반복되었다. 이 스킬은 그 절차를 표준화한다.

## 절차

### 1. 프로젝트 파악
- CLAUDE.md / AGENTS.md / docs를 읽고 **금지사항과 검증 명령**을 먼저 확정한다.
- 아키텍처 지도를 짧게 정리 (진입점, 데이터 흐름, 상태의 진실이 어디인지).

### 2. 기준선 검증
- 프로젝트 검증 스위트(CLAUDE.md/AGENTS.md의 검증 명령)를 먼저 실행해 현재 통과/실패 기준선을 기록한다.

### 3. 실사용 시나리오 점검
- 개발 서버를 켜고 핵심 사용자 흐름을 preview/Playwright로 직접 수행 (가입→핵심 기능→저장→재방문 등).
- 콘솔 에러, 네트워크 실패, 빈 상태·에러 상태 미처리, 모바일 뷰포트 문제를 수집.
- 발견 문제는 심각도(치명/불편/사소)로 분류해 목록화한 뒤 수정.

### 4. 코드 부채 정리
- 죽은 코드, 중복 컴포넌트, 미사용 의존성, 타입 우회(as any) 제거. 제거 전에 검색 가능한 모든 호출 경로(설정 기반 로딩, 플러그인, 동적 로딩·리플렉션 포함)를 확인하고, 사용 경로를 배제하지 못하면 유지한다.
- **동작 변경 없는 리팩토링만.** 스키마·프롬프트·안전 불변식 등 프로젝트 금지 영역은 건드리지 않는다.
- 커밋은 하지 않는다. 사용자가 커밋을 요청하면 ship 절차로 인계한다 (진단 수정 / 실사용 수정 / 리팩토링의 논리 분할은 ship이 담당).

### 5. 최종 검증 및 보고
- 검증 스위트 재실행으로 기준선 대비 악화가 없음을 증명.
- 한국어로 보고: 발견 문제 목록(심각도별), 수정 내역, 남긴 이슈(수정 안 한 이유 포함).

## Task 도구 사용
긴 작업이므로 단계마다 TaskCreate/TaskUpdate로 진행 상황을 기록해 "이어서 해" 재개가 가능하게 한다.
